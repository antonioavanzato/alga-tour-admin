## Общая архитектура (одинаковая для всех трёх проектов)

Каждый проект — на **отдельном биллинг-аккаунте** Yandex Cloud, полностью на
**бесплатном тарифе** (не грант). Схема:

```
Форма на сайте  ──POST──►  Cloud Function (intake)  ──►  YDB serverless (заявки)
                                     │
                                     ├──►  Telegram Bot API (пуш владельцу)
                                     └──►  Web Push (PWA-админка на iOS/Android)

Таймер-триггер (cron) ──► Cloud Function (keep-warm + дослать неотправленное)
```

**Ключевые принципы, которые заложены во все проекты:**
1. **Сначала запись в БД, потом уведомления.** Заявка сохраняется до отправки в
   Telegram/пуш — данные не теряются, даже если уведомление упадёт.
2. **Таймауты на всех внешних вызовах** (`AbortController` / `Promise.race`),
   чтобы функция не висела и не ловила 504.
3. **Дослыл (resend pending).** Неотправленные уведомления помечаются
   `pending` и досылаются таймером.
4. **Прогрев (keep-warm)** — таймер будит функцию, чтобы первая заявка после
   долгого простоя обрабатывалась мгновенно (без холодного старта).
5. **Всё в бесплатных лимитах** с большим запасом (см. ниже).

**Бесплатный тариф Yandex Cloud (на аккаунт, в месяц, постоянный):**
- Cloud Functions: 1 000 000 вызовов + 10 ГБ·ч
- YDB: 1 000 000 операций + 1 ГБ хранилища
- API Gateway: 100 000 запросов
- Message Queue: 100 000

На каждом аккаунте стоит **бюджет-триггер 1 ₽** («Стоимость потребления») —
сработает при малейшем платном расходе.

## Проект 1 — ALGA (alga-tour.com)

Туристические заявки с сайта → Telegram + PWA-админка.

- **Сайт/форма:** alga-tour.com/booking (RU + EN версии формы).
- **Backend:** 3 Cloud Functions — `intake` (приём заявки), `admin-api`
  (авторизация админов, выдача заявок), `notify` (таймер: пуш + дослыл).
- **Хранилище:** YDB serverless, таблица заявок.
- **Админка (PWA):** `alga-tour-admin/admin/index.html`, API_URL
  `d4ed9gsamgdaflofq6jj`. Опрос каждые 30 сек. Есть поиск с кнопкой очистки (×),
  нативные кнопки WhatsApp/Telegram, JWT-авторизация (bcrypt).
- **Уведомления:** общий Telegram-бот + все 3 админа видят одни и те же заявки.
- **Загрузка лимитов:** ~13% (большой запас).
- **Репозиторий:** `antonioavanzato/alga-tour-admin`.

## Проект 2 — AVANZATO (avanzato.ru)

- **Задача была:** «телеграм-тишина» — заявки терялись, т.к. Telegram
  вызывался ДО записи в БД и без таймаута.
- **Что починили:** запись в БД перенесена перед Telegram, статус
  `tg_status='pending'`, best-effort отправка + `resendPending`, таймаут 4000 мс
  на Telegram (`AbortController`).
- **Файлы:** `backend/avanzato-src/handlers/orders.js`,
  `backend/avanzato-src/telegram.js`.
- **Загрузка лимитов:** ~2–5%.
- **Результат:** заявки доходят мгновенно даже после долгого простоя,
  ничего не потеряно.

## Проект 3 — DARIA (Дарья Лукьянова, запись к преподавателю музыки)

- **Задача была:** заявка приходила в админку, но не в Telegram.
  Причина — в `chat_id` был только один получатель (Даша), Антон не был добавлен.
  Это была не ошибка кода, а конфигурация.
- **Что сделали:**
  - Мульти-чат в `sendTelegram` (несколько `chat_id` через запятую) + таймаут 5000 мс.
  - Таймаут 6000 мс на Web Push (`Promise.race`).
  - Прогрев (keep-warm) через таймер каждые 5 минут.
  - Поменяли вкладки местами: сначала «Заявки», потом «Календарь».
  - Сделали красивую PWA-иконку (золотые ноты ♫ на тёмном градиенте):
    `icons/icon-192.png`, `icon-512.png`, `icon-512-maskable.png`.
- **Backend:** `yc/backend/index.js`. Активная версия `d4eo4kkbh0p85nm7gi1j`,
  таймер `daria-keepwarm` (каждые 5 мин).
- **Загрузка лимитов:** ~1–2%.
- **Репозиторий:** `antonioavanzato/darialukianova_booking` (админка на GitHub Pages).

## Безопасность
- Утёкшие секреты (токены ботов, пароли, JWT/VAPID) были найдены в истории git,
  вычищены, история переписана (force-push), ключи и пароли **ротированы**.
- В `.gitignore` добавлены все шаблоны ключей/env (`*key*.json`, `.sa-*.json`,
  `.deploy.env` и т.д.).
- OAuth-токены больше не годятся для обмена на IAM (блок Яндекса после 2026-06-01) —
  используются авторизованные ключи сервисных аккаунтов (JSON).

## Паттерн безопасного деплоя (для будущих правок)
1. Сохранить env-переменные: `yc serverless function version get`.
2. Собрать/поправить исходники, оставить бэкап `.orig`.
3. Задеплоить **новую** версию (старая остаётся для отката).
4. Сохранить env / сервисный аккаунт / таймаут / память.

## Итог
Все три формы отправляют заявки в Telegram и в PWA-админку без сбоев,
данные не теряются даже после долгого простоя, все три проекта укладываются
в бесплатные лимиты с большим запасом.
